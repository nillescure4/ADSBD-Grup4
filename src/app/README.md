# Game Atlas · Streamlit application

From the repository root, with the virtual environment activated:

```powershell
python -m pip install -e ".[dev,app]"
python -m streamlit run streamlit_app.py
```

Open http://localhost:8501. The server runs locally. No generative model or new
API keys are required. All interface text and application documentation are
in English. Source descriptions retain their original language.

## Pages

- **Home:** project context, sources, architecture and counts from the real
  ChromaDB catalogue. Missing data is reported without preventing navigation.
- **TASK 1 · Similarity** (`/similarity`): working text-to-text search. Image
  and audio modes remain disabled until their retrieval pipelines are ready.
- **TASK 2 · Multimodal** (`/multimodal`): preview of future cross-modal search;
  no search execution, simulated results or CLAP connections.
- **TASK 3 · Generation** (`/generation`): preview of the future assistant with
  context and sources; no external model is invoked.

## Text search prerequisites

The database must exist at `data/exploitation/chroma`, with the `texts_clip`
collection generated by the process documented in `src/exploitation/README.md`.
The interface does not create collections or run ingestion. It does not modify
catalogue documents, metadata or embeddings, nor original data in MinIO.

Queries use the same OpenCLIP model and checkpoint as the indexed vectors.
The configuration fingerprint and cosine metric are verified. First use may
load or download model weights, which are subsequently kept in memory.
A lock serializes model usage across sessions. Queries of up to 4,000 characters
are split according to the tokenizer, without truncation.

Each game appears once with its maximum similarity over query/document chunk
pairs. By default, only the latest snapshot with indexed vectors is considered
for each game. Disabling that option includes the complete indexed history.
Scores are similarities rather than probabilities; relevance is not guaranteed.
This implementation retrieves all chunks for correct grouping and filtering
of the small local corpus. A scalable retrieval strategy will be needed if
its size increases substantially.

Search only requires the local database. Each result also loads its exact
Trusted snapshot from MinIO, checking its SHA-256, row, game ID, full text hash
and matching passage. It displays the complete `description_clean`, RAWG rating,
Metacritic score, release date, playtime, genres, platforms, developers and
publishers. The complete description appears immediately after the result title,
with its best-matching passage in bold. A note in Text mode explains why long
descriptions are split into passages and how the highlighted passage determines
the ranking. Source text is HTML-escaped, preserving paragraphs and punctuation.
Technical fields and provenance are not exposed as result expanders; provenance
remains available internally for verification. Structured JSON columns are decoded for presentation.
Missing values are labelled explicitly; zero values are preserved.

The similarity score still comes from the best-matching chunk, rather than an
embedding of the complete description. Details always belong to the matching
snapshot, including when historical search is enabled; they are never replaced
with values from a newer snapshot. Verified snapshots are cached by bucket,
object key and hash for two minutes.

If Trusted is unavailable or fails verification, search results remain visible
with an explicit warning and only the indexed passage. A partial passage is
never labelled as a complete description. Data does not need to be ingested
again. Update the catalogue using independent pipelines and reload the page.

TASK 2 images and audio will need to be resolved from their original assets and
provenance. OpenGameArt audio consists of independent CC0 music tracks, not
soundtracks associated with the games. CLIP and CLAP will require separate
rankings: their scores cannot be compared directly.

## Verification

```powershell
python -m pytest tests/unit/test_app_text_search.py tests/unit/test_app_trusted_details.py tests/unit/test_streamlit_app.py -q
```

Interface tests use Streamlit AppTest without downloading weights or modifying
real data. They check the English interface, rendering, search interactions,
missing-data states and disabled actions for pending tasks.
